# Harness 壳子

> **调用**：阶段 ⑤ 要搭 Agent 运行时壳子、或判断「换业务要不要重写」时用
> **触发**：Harness、运行时、感知规划行动观察、LLM 适配器、Tools 注册表、换业务只换右侧
> **路径**：`project-kickoff-skill/references/Harness壳子.md`
> **边界**：只给通用壳子结构；不含任何具体业务的工具与技能

    用户任务
      ↓
    ┌─ Agent Harness 运行时（通用）─────────────────────────┐
    │ ① 感知·组装上下文（拼 prompt：任务 + 记忆 + 工具说明）  │
    │ ② 规划 Plan（LLM 决策：下一步调哪个工具 / 技能？）      │
    │ ③ 行动 Act（调用 Tool / 执行 Skill）                    │
    │ ④ 观察 Observe（结果写 Memory · 判断是否完成）          │
    │    ↺ 回到 ①；完成后 → 结构化结果交给 UI                │
    └────────────────────────────────────────────────────┘

    左：LLM Engine 适配器（随时换大脑）
        Memory（短期：本次对话 / 任务状态；长期：向量库语义检索）
    右：Tools 注册表 ＋ Skills 库   ← 业务特定，换业务只换这里
    底：Tracing / Eval（留痕可回放、token / 耗时、质量评估、失败重放）

## 复用边界

壳子（感知 → 规划 → 行动 → 观察）一次搭好、永久复用；**换业务只改右侧业务特定的 Tools 与 Skills，壳子不动**。
换「抖音专家 / 知乎专家」这类场景同理：不动运行时，只换右侧。
