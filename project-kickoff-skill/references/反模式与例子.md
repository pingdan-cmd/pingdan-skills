# 反模式与例子

> **调用**：阶段踩坑要对照反模式、或画工作流要把「人的动作」翻译成技术需求时
> **触发**：反模式、踩坑、现象对策、销售找客户、五步、翻译技术需求、工作流例子
> **路径**：`project-kickoff-skill/references/反模式与例子.md`
> **边界**：只给对照与范例；不替代阶段判据，不新增流程闸门

## 一、反模式（现象 → 对策）

| 现象 | 为什么坏 | 对策 |
|---|---|---|
| 一上来就「帮我做个 X」 | 缺给谁 / 解决什么 / 放哪，产出没人要 | 回门禁 G1 补目标三行，答不上标【假设】 |
| 需求里没有「先只做一个」 | 一次做大，出问题定位不到 | 需求模板写死第一小步，附完成定义与失败回退 |
| 只写需求、不封工具 / skill / 壳子 | AI 只能聊天、干不了活 | 阶段 ⑤ 补齐工具卡片与 skill 六部分 |
| 跳过数据直接写功能 | 结果无法复用、无法增量 | 阶段 ③ 先出字段表 + 唯一键，不产数据则标注跳过 |
| 把工作流写成愿望清单 | 不是可执行步骤，模型自行规划会飘 | 阶段 ② 每步标执行者 / 验收人 / 异常去向 |
| 同一规则写进多个文件 | 改一处漏一处，互相冲突 | 正本只写一处，其余放指针 |
| 把节流 / 种子层写成所有项目必填 | 爬虫特有约束，误导非采集项目 | 需求模板 §二 变体按需挑，通用核不留它们 |

## 二、例子：销售找客户五步 → 技术需求

| 没 AI 时销售这么做 | 翻译成技术需求 |
|---|---|
| 1 登录 | 登录模块 |
| 2 搜关键词刷帖 | 采集（搜帖） |
| 3 翻评论区找人 | 采集评论 |
| 4 看主页 / 兴趣 | 采集主页 / 点赞收藏 |
| 5 判断要不要联系 | Agent 分析（需求 / 性格 / 切入） |

五步人的动作，直接告诉了你技术要做什么。**先把人的动作理清楚，技术需求自己就浮出来了。**
