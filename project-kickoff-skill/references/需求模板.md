# 需求模板

> **调用**：阶段 ④ 要把需求写成可交给 AI 的工程级文档时
> **触发**：需求模板、工程级需求、填空模板、交付载体、角色目标、功能清单、合格检查
> **路径**：`skills/superpowers/skills/项目启动准备/references/需求模板.md`
> **边界**：只给模板与检查清单；不替用户填内容、不猜目标、不一次实现多个功能

## 一、通用核心（所有任务都填）

【】处按本项目补，不照抄示例；写不下去就停，不硬编（卡住 → `problem-templates`）。

    # 交付载体（产出物定义，最终不可缺）
    平台：【按用户原话填，不替他编】
    形态：【云文档 / 笔记 / 页面 / 文件夹 / 脚本】
    名称：【用户给的文件名】
    正本在哪：【唯一真相源路径】
    交付视图放什么、不放什么：【一句话边界】

    # 角色
    你是一名资深【领域 + 身份】。

    # 目标
    业务目标：为【谁】做【什么】提供【什么支撑】，产出【形态】，以【判据】算成。
    工程目标：以【项目名 / 链接 / 现成底座】为基础实现【模块名】；不从零造轮子。

    # 功能需求（逐个实现、逐个验证）
    先查 skills/README.md ／ 问题路由表.md，现成能力直接路由复用；确实没有再逐条列：
    【函数名(入参) → 返回什么】× N 条

    # 数据
    存什么：【字段表】
    怎么连：【关联关系 / 唯一键】
    （不产生持久数据的任务可整段跳过）

    # 合规红线（只列本项目适用的，见 §三）
    【授权边界 / 平台规则 / 个人信息保护 / 越权边界】

    # 交付方式
    交付 = 能直接运行的产物 + 结构化结果（字段固定，下游能直接读）。
    先只实现【第一个函数】，跑通判据：【完成定义】，失败时：【失败回退】，我再决定要不要做下一个。

## 二、可选变体（按任务类型挑，非必填）

### 爬虫 / 采集类

- 请求节流：每分钟上限 + 随机间隔；失败重试：指数退避，超 N 次记日志跳过。
- 数据两层：种子层（先存线索）＋ 详情层（深挖后）；去重键、断点续爬标记（seed 带 status）。
- 登录态 / 代理走配置，不写死在代码里。

### 文档 / 内容类

- 交付形态：docx / pptx / 表格 / 网页；先定版式来源再填内容。
- 引用与出处：每条结论能指到来源；无来源标「未提及」，不推测。

### 分析 / 报告类

- 输入字段＋来源固定；输出严格 JSON，含「证据原文」字段。
- 信息不足写「资料不足，无法判断」，绝不臆测。

## 三、通用合规底线（所有任务）

- 授权：只处理用户有权处理的数据与平台内容。
- 平台规则：遵守目标平台的服务条款与访问频率限制。
- 个人信息：不采集、不留存、不输出隐私敏感信息。
- 越权边界：只做被授权的动作（如只分析，不替用户发送 / 付款 / 发布）。

## 四、合格检查（交出去前逐条过）

- [ ] 角色 / 目标按本项目补，含「给谁 / 产出形态 / 判据」
- [ ] 功能先查过路由表，现成能力已复用，没重复造轮子
- [ ] 每条功能可验证（有输入 / 输出判据），且先只做一个
- [ ] 数据字段、关联、唯一键齐（不产数据则标注跳过）
- [ ] 合规四项按适用情况在（授权 / 平台 / 个人信息 / 越权）
- [ ] 交付是结构化结果、字段固定
- [ ] 第一小步写了完成定义与失败回退
- [ ] 需人和 AI 共同完成：计划人给、AI 施工、关键确认人审、决策人做
- [ ] 目标三行与交付载体已落定（见 SKILL.md §1，此处不重复设闸）

> 完成定义：可核对的判据，不写「性能要好」这类模糊说法。
> 失败回退：跑不通时退回哪一步、保留什么证据、何时停止重试。
