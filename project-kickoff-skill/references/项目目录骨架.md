# 项目目录骨架

> **调用**：新项目开工建目录、项目文件散落要归位、查项目台账规则时
> **触发**：项目目录、建项目、文件夹结构、骨架、初始化、台账、_log、归位
> **路径**：`project-kickoff-skill/references/项目目录骨架.md`
> **边界**：只管新项目目录与命名；台账操作细则正本在项目的 `_log/_说明.md`

## 一、骨架全图（目录号与阶段号一一对应）

    <项目名>/
    ├── 00-立项-<项目名>.md      # 必建：立项书
    ├── README.md                # 必建：一页导航
    ├── _log/                    # 必建：项目台账
    │   └── _说明.md             # 台账细则正本
    ├── 01-人与问题/             # 阶段 ①
    ├── 02-工作流/               # 阶段 ②
    ├── 03-数据/                 # 阶段 ③
    ├── 04-需求/                 # 阶段 ④
    ├── 05-工具与技能/           # 阶段 ⑤
    └── 06-验证与交付/           # 阶段 ⑥

## 二、必建 3 件

- `00-立项-<项目名>.md`：目标三行（给谁用／解决什么／什么算成）＋ 交付载体（平台＋形态＋文件名＋正本位置）＋ 验收判据。
- `README.md`：一页导航——这个项目是什么、推进到哪、文件地图（每行：路径 → 管什么）。
- `_log/`：项目台账，细则见 `_log/_说明.md`（本文只留指针，不抄第二遍）。

## 三、台账四类（判据）

| 类 | 判据 |
|---|---|
| 疑问 | 等用户回答、尚未定论的事 |
| 意外 | 与预期不符、但已确认发生的事实 |
| 问题 | 已确认、需要修的缺陷 |
| 成果 | 已验证通过的产出 |

> 四类固定，不新增第五类。每条怎么写、按版本切文件、与系统日志不双写等操作细则，
> 正本在项目的 `_log/_说明.md`，本文不重复。

## 四、阶段目录（哪阶段有产出建哪个）

| 目录 | 对应阶段 | 装什么 |
|---|---|---|
| `01-人与问题/` | ① 理解人 | 人群、标签、真问题、证据来源 |
| `02-工作流/` | ② 画工作流 | 编号步骤表、流程图 |
| `03-数据/` | ③ 数据 | 字段表、关联、唯一键 |
| `04-需求/` | ④ 工程级需求 | 填好的需求模板 |
| `05-工具与技能/` | ⑤ 工具+技能+壳子 | 工具卡片、skill 六部分、Harness |
| `06-验证与交付/` | ⑥ 第一小步 | 最小可运行产物、跑通判据、最终交付物 |

- 产出物文件名带阶段号，落对应目录；不散落项目根。
- **不建空目录**：没有产出就不建。
- 不临场造目录名：要放的东西不在上表 → 先问用户，不发明 `资料/`、`tmp/`、`附件/`。

## 五、归位规则

- 老项目默认不动；本规范只管新项目。
- 用户点名要归位时：先出「原路径 → 新路径」清单，确认后再移动，不边列边移。

## 六、原版与口径

- 原版只读不覆盖：改立项出 `xxx-校正版.md`，原版与旧 log 只读留档、不删。
- 若项目另有行为准则，以其为准；本骨架不预设任何库内专有文件。
